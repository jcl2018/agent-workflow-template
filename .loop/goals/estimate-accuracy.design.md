## Problem Statement

The live board's time estimates come from the size-based model that estimate-model shipped in v0.22.1: similar goals by done lines and touched areas, per-step medians, a whole-goal lift (STEP_UP 60 s per extra unit), pace, ranges, "rough" and a 3x stall rule. A leave-one-out backtest over this repo's finished runs says that model is the least accurate option on the table: its whole-goal estimate is typically off by x3.3 to x3.5, while plain size-blind per-step medians are off by x2.3 to x2.4. The owner approved this goal: use whichever model backtests best, and show its typical error.

Three known defects ride along:

- The 3x stall rule has no floor, so a step whose estimate is 3 minutes reads stalled after 9 minutes.
- A held goal (running, no worker) with no pause entry keeps adding the time since its last log entry to its current step, so its time left and overrun grow while nothing runs. Today's board shows this: five goals read stalled at 4 to 7 hours on steps estimated at 35 to 43 minutes. Log entries like `session report: held at plan for ... (owner)` and `holding before qa as asked` are not treated as pauses either, so past runs also carry owner-hold time as work time.
- `board_status.py` is 19,518 bytes, 95% of the 20 KB script limit; it must drop under 90% (18,432 bytes).

## What Makes This Cool

The board stops asserting a model and starts measuring one. Every render it scores each candidate model against the goals that already finished, uses the winner, and prints how wrong it typically is, so the owner can read "31m to 1h10m left" next to "typically off x2.3" and know how much weight to give it. When the repo's history changes shape (say, size starts to matter), the board switches models by itself.

## Premises

Measured 2026-11-10 by a scratch leave-one-out script over 62 finished runs with logged time (78 run records in all), whole-goal estimate as if queued, error = median of |ln(estimate / actual)| shown as x e^error:

| Candidate | Typical error |
|---|---|
| Size-blind per-step medians (sum of each step's median over all other finished goals) | x2.33 |
| Whole-goal median (no steps) | x2.44 |
| Geometric blend of the two per-step models | x2.91 |
| Size-blind medians plus a 60 s per extra unit tilt | x2.70 |
| Size-based rule (v0.22.1, ENG-15) | x3.33 |

1. Size does not predict time on this repo's data; the size rule is the worst candidate measured. Agreed (measured, and matches estimate-model's own premise P2').
2. The owner's rule decides, not this design: the board computes the backtest live and uses the lowest-error candidate; on today's data that is size-blind per-step medians, but the code must not hard-wire it. Agreed (done line 1).
3. The frozen monotone criterion (`est-monotone`) still binds every candidate. It asserts internal seconds (`estimate(...)[0]` strictly increasing over three sizes), and `est-issue-96` asserts internal seconds differ plus each estimate inside its similar goals' range on a fixture where time grows with size. A size-blind model meets `est-monotone` with a 1-second-per-extra-unit tilt: strictly longer for a larger goal, negligible on the log error. A 60 s tilt costs x2.33 -> x2.70, so the tilt for size-blind candidates is 1 s, not STEP_UP. Agreed.
3a. Consequence, accepted explicitly: when `steps` wins (today's real board), two queued goals of different sizes print the same rounded estimate. Issue 96 was that every goal read a fixed 15 minutes regardless of history; this goal's owner rule ranks backtested accuracy above size sensitivity, and on this repo size does not predict time, so equal printed estimates are the honest output. The accuracy line names the model in use, which explains the equality. Where size does predict time, the backtest picks the size rule and the estimates differ in print too. Leave-one-out is honest: inside a fold the held-out goal is not its own similar goal, so a group of 5 similar goals leaves only 4, below `SIMILAR`, and the size rule falls back to every finished goal in that fold. The `est-issue-96` fixture has exactly 5 finished goals per size group (10 in all), so as it stands the size rule cannot win its backtest and a size-blind winner would put both estimates between the groups, failing the row. Fix (test data only, row text unchanged): `check_issue_96` gets a sixth finished goal per group (sizes (2,1) and (7,5), times inside each group's existing range, so the asserted range is unchanged), giving 5 similar goals per fold; the size rule then predicts each held-out goal from its own group while `steps` and `blend` predict from the pooled mix, so the size rule wins by a wide margin (pooled medians are off by about x3 to x5 against groups of 10-30m and 90-150m). The `est-monotone` fixture (also 5 per group) passes on internal seconds through the 1 s tilt whichever candidate wins, so it needs no change. Before claiming any fixture's winner, the implementation prints the backtest scores for every existing fixture with 10 or more finished goals and records which candidate wins. The new row `est-steps-monotone` covers a 12-goal fixture where `steps` wins and a larger goal still gets a strictly longer internal estimate. Agreed.
4. With few finished goals the backtest is noise. Below 10 scorable finished goals, the board keeps the size rule (today's behavior) and says the error is not known yet. Only toy fixtures with fewer than 10 finished goals stay on the size rule this way; fixtures with 10 or more (`est-monotone`, `est-issue-96` and any others found) go through the chooser (see 3a). Agreed.
5. Ranges stay each model's own quartile ranges (sum of per-step q25 and q75, lifted); the typical error is shown once on the board, not folded into every range. That changes no existing range row and keeps one source of truth for the error. Agreed.
6. A held goal, and a goal whose log says it is held, counts no time for its current step until its next log entry. Agreed (done line 4, and it cleans the backtest's training data too).

Add the backtest and switch inside `board_status.py`, floor the stall rule, skip the held tail. Smallest diff, but it pushes the file further over the limit and cannot meet done line 4's size clause. Rejected: fails a frozen done line.

More honest ranges, but it rewrites `est-range-text`, `est-overrun-range` and `est-partial` expectations, which are frozen criteria of the previous goal, and done line 2 is already met by showing the error once. ### Candidates and the backtest (done line 1)
- Candidates are named per-step tables, each run through the same monotone envelope as today's lift:
  - `steps`: every step's plain median, q25, q75 over all other finished goals that logged it (size-blind); envelope tilt 1 s per extra unit.
  - `size`: today's ENG-15 rule unchanged (similar goals within 1, falls back to all; STEP_UP 60 s lift).
  - `blend`: the geometric mean of `steps` and `size`, per step and per range end; envelope tilt 1 s.
- `backtest(runs, at, root)`: for each finished goal with logged time and a known total, estimate it as queued from all other finished goals, per candidate; score = median |ln(estimate / actual)|. Returns `{name: (score, n)}`.
- `chosen(runs, at, root)`: the candidate with the lowest score; an exact tie goes to the first in the order `steps`, `size`, `blend`; with fewer than `MIN_BACKTEST` scorable goals it returns `size` with no score. Memoized in `MODEL` under the same key as today (slug, status, updated of every run), so it is recomputed exactly when a run finishes or changes, and once per board render otherwise.
- `steps_for` / `lifted_steps` use the chosen candidate's table. Pace, `step_left`, overrun ranges, partial and "rough" (fewer than 5 similar goals, unknown size, a step with no estimate, or a clamped size) keep their current rules for every candidate.
- Scoring set (one definition): a finished goal is scorable when its `flow_seconds` total is above 0 and every candidate returns an estimate for it as queued from the other finished goals. All candidates are scored on that same set, so their medians are comparable; a rough or partial estimate is scored by its `left` value as is. `MIN_BACKTEST` counts this common set. A goal the size rule cannot size (missing or unreadable goal file) is still scorable: the size rule then estimates from all goals with no lift, exactly as the board would show it.
- Budget, measured 2026-11-10 on the real runs (62 scorable of 78 records) with the existing code: building `MODEL["done"]` (sizes and `flow_seconds` for every finished goal, goal-file reads included) takes 0.04 s; the size rule's 62 leave-one-out folds through `lifted_steps` on that cached model take 0.12 s. `steps` is per-step sorted lists with one value removed per fold (negligible); `blend` reuses both tables. So the whole backtest is about 0.2 s. The memo lives in the process only: the board is a fresh process per render, so the backtest runs once per render (and again in a long-lived process only when the run key changes). Budget: under 0.5 s for the real run count; the toy row `est-backtest-speed` holds 100 fixture goals under 1 s.

### Showing the error (done line 2)
- Every goal already shows `<low> to <high> left[, rough]`; that stays.
- `accuracy_text(runs, at, root)` returns one line, at most 60 columns, for example `estimates: step medians, typically off x2.3 (62 goals)`, or `estimates: size rule, error not known yet (4 goals)` below the threshold. It is printed under the Finish line.

### Stall floor (done line 3)
- `stalled` flags a step only when `spent > max(STALL x estimate, STALL_FLOOR)`, with `STALL_FLOOR = 900` seconds. The printed estimate stays the pace-adjusted estimate.

### Held goals stop accruing (done line 4)
- `flow_seconds(run, at, held=False)`: when `held` is true the live tail (time since the last entry) counts nothing. A gap that follows a hold entry counts as a pause, like a gap after `stopped`, `failed` or `waiting` today. A hold entry is exactly: a log entry whose text after the timestamp starts with `session report:` and contains the phrase `held at`, `held before` or `holding before` (word-bounded). The forms seen in this repo's runs are `session report: held at plan for test-lanes (owner)`, `session report: held before ship try 3 for test-lanes (owner)` and `session report: worker · board-held: review done (...); holding before qa as asked`; each is a test case. The phrase rule (not a bare `held`) keeps a slug such as `board-held` and a negation such as `no longer held, resuming` from pausing; both are negative test cases. This fixes both live held goals and owner-hold gaps in finished runs the backtest learns from.
- `estimate_full`, `pace_of`, `step_now`, `overrun` take a `held` set (default empty) and pass `run["slug"] in held` down. `board_items(..., held=())` passes it on.
- `live_board.py` changes exactly two lines: `bs.board_items(..., held={r["slug"] for r in held})` and the Finish block appends `bs.accuracy_text(runs, at, root)`. Both are call sites only.
- Owner-gate waits already pause through the `waiting` status and `waiting:` entries; no change beyond the held words.

The board's chosen model equals the lowest backtest score in both; break: force a fixed candidate.

### R3-1 — completeness (minor)

**Problem**

> Persisting R2-8, in part. The size-wins data set now has 6 goals per group at 10-20m and 100-200m, so the size rule clearly wins. The steps-wins set ('both groups share the same spread of times') still has no data that guarantees a clear margin. On that set the size rule predicts from its own group of 5 and `steps` from the pooled 11, both drawn from the same distribution, so their scores can be close. If the size rule's lift is near zero for a matching group, the only gap between them is sampling noise. `blend`, the geometric mean of two near-equal estimates, can average out that noise and score lowest. The claim that 'step medians must win' then fails, even though the chooser itself works.

**Remedy**

> Choose the steps-wins data so `steps` beats both `size` and `blend` by a stated margin. For example, give the large-size group the same times but enough extra units that the 60 s per-unit lift pushes size and blend estimates measurably high. Or assert only that the chosen model equals the lowest score, and print and record the three scores for each set before fixing the expected winner.

### R3-2 — completeness (minor)

**Problem**

> Persisting R2-3: the hold phrase rule still matches a negated or resumed entry that contains a listed phrase, for example 'session report: no longer held at plan, resuming'. Only the bare 'no longer held, resuming' is a negative case.

**Remedy**

> Accept this residual false positive explicitly, or exclude entries containing 'no longer' or 'resum' and add that negative test case.

### R3-3 — completeness (minor)

**Problem**

> Persisting R2-4: the held set is passed only from live_board.py. board.py and cost.py call the same estimate functions with the default empty held set, so any estimate they show for a held goal still adds idle time.

**Remedy**

> State whether board.py and cost.py show live estimates for held goals and, if they do, pass the held set or note why they are out of scope.

### R3-4 — clarity (minor)

**Problem**

> Persisting R2-5: 'rough' (fewer than 5 similar goals) is defined on size similarity, yet the design keeps it 'for every candidate'. Under the size-blind `steps` or `blend` candidates, it is unclear which goals count as similar.

**Remedy**

> Define the rough condition per candidate (for example, the number of goals that logged the step for `steps`).

### R3-5 — clarity (minor)

**Problem**

> Persisting R2-6: the memo key (slug, status, updated of every run) omits goal-file contents. In a long-lived process, editing a goal file without touching its run leaves a stale size and a stale backtest, and the design does not say that staleness is accepted.

**Remedy**

> State that this staleness is accepted (the same as today, and moot for a fresh process per render) or add goal-file mtime to the key.

### R3-6 — clarity (minor)

> Persisting R2-7: the Success Criteria still require the real board to show step medians with a typical error 'near x2.3'. That figure was measured before the hold-entry pause changed the training data, so the live figure may move.

**Remedy**

> Phrase the criterion as the board's chosen model matching the lowest backtest score on real data, with x2.3 as an expectation, not a pass condition.
