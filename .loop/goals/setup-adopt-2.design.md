## Constraints

- Frozen done lines; Reviewed wiki lines untouched (docs/wiki/Setup.md: SET-2, SET-6, SET-7, SET-8, SET-9 and others). Changes go to Usage, Tests and Unreviewed text only. SET-1 stays Unreviewed text and is not reworded.
- Milestones are free form (milestone-freeform): setup makes and asks for no milestone, issues carry their feature or group, `feature:<Page>` labels stay behind `feature_labels` (off). No per-feature milestone returns.
- Scripts stay under 20 KB and health warns at 90% (18432 bytes). `setup.py` is 17243 bytes: it cannot grow by more than a few hundred bytes, and the next goal (ci-minutes-template) edits it too. New logic goes in new small modules.
- Other repos already adopted the template: nothing may rename a loop file or break `update` (142 references to `.tsv` across 32 skill files).
- No private names, paths or emails in anything committed. No model call, no real GitHub write in any test (the existing `dev/toy/fakegh` stand-in).

## Premises

1. "Never blocks" means setup always finishes what can be written and turns everything else into a named gap with its fix. A refusal is kept only where finishing is impossible or unsafe (not a git repo, a dirty agent file, a private name, local setting or private value on a line the adoption itself adds, the repo's own commit hook refusing). Every such refusal leaves nothing written: tree, branches, index and the home folder are as before.
2. The adoption verdict is health: the check records the start, the same full check after adopting is the result, and a non-green verdict is a list of gaps each with its fix, not a failure of setup. Setup exits 0 whenever the adoption is on its branch.
3. The old goal setup-fit's "refuses to finish with a bare agent_command" is superseded by the owner's "never blocks" (owner 2026-11-10: "Approve 1, 2, 3."). The bare command becomes a gap (a new Adoption health rule names it and its fix line), not a refusal.
4. Existing wiki lines stay: the three-layer wording in SET-2 is met by a resolver and `settings show`; no reader of settings (about 40 scripts each read `.loop/config.json` themselves) is rewritten.
5. A security guard in someone else's repo is theirs to change: setup never edits a hook or script that rejects tracked files; it names the exemption and stops cleanly.

## Approaches Considered

### Approach A: patch each defect in place (S, low risk)
Fix 119, 120, 127 inside `survey.py`, `setup.py`, `seed.py`; add one toy script. Fewest files, but it pushes `setup.py` past the 18 KB warning, leaves done lines 2, 3, 5, 6 (verdict, layers, `--from`, local-setting refusal) unmet, and keeps refusals half-written. Rejected: it does not meet the frozen lines.

### Approach B: small modules around the existing flow, transactional apply, health at both ends (M, medium risk) (recommended)
`setup.py` stays the entry point and becomes thin wiring. New modules own the transaction and rollback, the verdict and filing, the private-value check, the layer resolver, the Home and README writer, and `--from`. Health gets two small Adoption rules for what setup can only name. Fixtures live in one new toy script. Reuses: `seed.decide/apply` (extended), `survey.ignored()` for the exact exception lines, `private.py hook staged`, health `check` and `file --group`, `criteria.py render`, `regression.py add/red`, `dev/toy/make.sh`, `fakegh`.

### Approach C: rewrite setup as plan-to-manifest-to-apply (L, high risk)
A `plan.json` of every action, applied by one engine with undo built in. Cleanest long-term; rejected as too large for this goal and it would collide with ci-minutes-template, which edits the same files next.

### Rejected during the session
- Another format for loop files (`.tsv` renamed or a second extension): 142 references in 32 files, breaks every repo that adopted the template and `update`'s keep-the-repo's-data promise; the cost is paid by others for one repo's guard.
- Probe the repo's pre-commit hook on a scratch index to predict a refusal: hooks can format or modify files; the real commit plus rollback is safer.
- Auto-editing a repo's privacy guard to exempt `.loop/*.tsv`: a security control is the owner's call (premise 5).
- Reading the model repo's private files for `--from`: private values must never travel (SET-9).

## Recommended Approach

Approach B. The decisions:

**Issue 120 (a refusal leaves nothing written).** New `adopt.py` holds `Txn`: before any write it records HEAD, the current branch, whether the setup branch exists, and for each path setup will write its prior bytes or absence (config, queue, findings, pages, `docs.tsv`, rows, workflows, START.md, agent files, `.gitignore`, rendered Tests.md). Order of a real run: plan, health start, write files, stage, scan and guards, commit, then (only after the commit succeeded) the git hooks, the private settings, issue filing and the health verdict. So nothing outside the plan's paths exists yet when a refusal happens, the hooks setup installs never run on its own commit, and hooks and private settings need no snapshot (a rerun after a refusal finds neither). Every refusal after the first write calls `Txn.rollback()`: unstage, restore or delete each path, switch back to the original branch, delete the setup branch if this run created it. If a restore step fails, rollback keeps going through the remaining paths and then prints `REFUSED: could not restore <paths> (<error>); the adoption is half undone. Fix: git status, then git checkout -- <paths>, git switch <original branch>, git branch -D <setup branch>` and exits 2. The private settings (`fill_private`) move to after a successful commit (a dry run and a refusal write nothing under the home folder). The bare agent command and the `.gitignore` conflict stop being refusals (below). Remaining refusals keep their `REFUSED:` wording and exit codes.

**Issue 127 (`.tsv`).** Keep `.tsv`. Two halves, both documented in a new `skills/workflow-setup/references/adoption.md` (SKILL.md points to it):
- `.gitignore`: the plan gets a `convert: .gitignore (adds ...)` line; setup appends, under one comment line, the exact exception lines `survey.ignored()` already computes (for example `!.loop/` then `!.loop/*.tsv`). Words already there are kept. This replaces `REFUSED: nothing written. Fix .gitignore`. `survey.ignored()` also reports where the rule came from (`git check-ignore -v`): only a tracked ignore file of the repo (the root `.gitignore` or a nested one) is edited; a rule from `.git/info/exclude` or the owner's global excludes file is not the repo's to change, so it yields `GAP: <file> ignores <path>. Fix: add <exact line> to that file`, and the adoption stages the plan's paths with `git add -f` so the commit still holds them.
- A repo guard that rejects tracked `.tsv` files: `survey.guards()` reads the repo's hook files (`.githooks/`, `.husky/`, `.pre-commit-config.yaml`, the git hooks folder, scripts named for a guard or hook) for `.tsv` and prints `GUARD: <file> mentions .tsv; if it refuses tracked data files, exempt .loop/*.tsv (docs, regression rows and runs)` in the dry run and the run. If the real commit is refused by a hook, setup rolls back, prints the hook's own output and the same exemption line, and exits 1 with nothing written; rerunning after the owner adds the exemption adopts. Never `--no-verify`.

**Issue 119 (zero-test check).** `survey.runs_tests` proves a command finds at least one test by the runner's real pattern, statically (nothing is executed): unittest discover uses `-s` dir and `-p` pattern (default `test*.py`), pytest uses `test_*.py` and `*_test.py` (or the file's own config), `go test` `*_test.go`, `cargo test` a `#[test]` or `tests/` file. The suffix-only case: `calc_test.py` under `tests/` now yields `python3 -m unittest discover -s tests -p '*_test.py'`. If neither pattern matches, the next fallback is a repo runner (`tests/**/run.sh`, `scripts/run-tests.sh`, `scripts/test.sh` that exists). With no proof the check list is empty, the existing `no fit: .loop/regression.tsv (no check command found)` line stays, and a `no-fit` finding is filed. One rule: surveyed guesses and CI-derived commands must pass the proof to become checks; a check the config already holds is kept as it is and noted (`NOTE: <cmd> finds no test files`) when it fails the proof.

**PR 83 (config keeps its own checks).** Re-implemented on current main, not merged from the stale branch: `seed.stored(config, old)` keeps a `checks` key the config already holds and the seeded land rows run every check joined by `&&`. Surveyed checks still become rows, not a setting, as before.

**SET-1 never blocks and files what doesn't fit.** `setup.py` collects gaps instead of refusing: a bare `agent_command` (`GAP: agent_command ... grants no tools. Fix: "agent_command": [...]`), pages with their own sections, unproven checks, a `.tsv` guard note. `adopt.py` writes one line per kind (so at most 5 lines; health's findings rule warns above 5) to `.loop/findings.md` as `- [adoption] <kind>: <subject, subject, ...>. Fix: <fix>`, the subjects listed inside the one line; a rerun rewrites that line only when its subjects change, so a second run changes nothing. A new Adoption rule `no-fit` in workflow-health turns each such line into one WARN row naming the subjects and fix, so the existing `health.py file --group adoption` files one issue per row with the group tag, and the feature when a page owns the path (health's own longest-prefix rule; the `feature:<Page>` label only when `feature_labels` is on). Filing is the group's own: it files every Adoption row health says to file (the new two and the existing four), and the test asserts the filed count equals the `WOULD` lines of `health.py preview --group adoption`. Setup runs that filing itself when `gh` is signed in and the repo has a GitHub remote; otherwise it prints `NOTE: N items left in .loop/findings.md; file them with workflow-health file --group adoption`. `--no-issues` or `LOOP_NO_ISSUES=1` skips, and the dry run prints `WOULD FILE`. Health marks dedupe a second run. A second new Adoption rule `agent-tools` names the bare agent command and its fix line.

**SET-1 docs format.** New `homewrite.py` writes the Home as the docs format wants it (marker, `# <repo>`, `## Features`, one table whose header is read from workflow-docs' `pageformat.HOME`, one row per feature page, linking the README section) and adds `## How to use` with one `### How to use <Feature>` section per page (intro line and the `| You say | What happens |` table with one row). The seeded Home no longer carries a `HOM-1` criterion or row. Seeded PRD pages are shaped so the only gap left is UNWRITTEN (a person must write them), and `docs.py check` is the oracle: the toy asserts no DOC-4, DOC-5, DOC-7, DOC-8 or link failure remains. If the README exists, only the missing section is added (words kept).

**SET-1 health first and last.** Before any write (dry run included, it is read-only and takes about 4 seconds) `adopt.health()` runs the sibling `workflow-health` `health.py check` and prints `HEALTH START: <the check's HEALTH line>` (or `HEALTH START: not measured (<reason>)`, the reason being that workflow-health is not beside workflow-setup, or that the check errored, crashed or ran past 120 seconds on a repo not yet adopted). After the commit it runs the same full check on the branch and prints `ADOPTION VERDICT: GREEN` or `ADOPTION VERDICT: GAPS (<n> fail, <m> warn)` followed by every FAIL and WARN line the check printed (each already carries its fix), or `ADOPTION VERDICT: not measured (<reason>)` when the run fails; setup exits 0 in every case. Lines per run: a dry run prints `HEALTH START:` and `ADOPTION VERDICT: not run (dry run)`; a real run and a no-change run both print `HEALTH START:` and `ADOPTION VERDICT:` (so the second run still states the repo's verdict). Usage text and the rows use these names only. The start state is also the second line of the adoption commit message. Exit stays 0 either way. `--no-health` or `LOOP_NO_HEALTH=1` skips (`dev/toy/reap.sh` exports it so existing toy tests are unchanged; the new tests unset it).

**SET-2 layers.** New `layers.py`, shown by `settings.py show [--repo DIR] [--json]`: one row per setting, `| setting | value | layer | home |`, layer being `default` (the template's table), `repo` (set in `.loop/config.json`), or `local` (set in the flow or health file under the owner's private folder, `$LOOP_FLOW`/`$LOOP_HEALTH` honored and named). Resolution is default, then repo, then local, with a later layer winning wherever a key appears in more than one. Today each setting has one home, so for one key the layers are default and its home; a private-home key found in the committed config is shown `repo (local setting in a committed file)` and is what SET-8 refuses. A cross-home override (a local file overriding a repo key) is not added: about 40 scripts read `config.json` themselves; `layers.resolve` is the single place to add it and is noted in the Usage text. The reference and `show` read the same table.

**SET-9 `setup --from <adopted repo>`.** New `borrow.py`, read-only on the model (a local path; no network). It reads the model's `.loop/config.json` and `.loop/docs.tsv` and prints `borrow:`, `adapt:` and `skip:` lines in the plan:
- Settings shape and flow: every repo-home setting on a portable allowlist whose value differs from the default becomes this repo's value: parallel, max_tries, cadence, criteria, criteria_max, review_depth, token_budget, the `*_minutes` budgets, step_limit, goal_levels, ci_levels, pool_size, digest_mail, regression_cron, health_cron, feature_labels, stale_branch_days, silent_minutes. Settings that widen what runs unattended or execute code are never borrowed silently: auto_approve, auto_merge, full_auto, mend, resume_on_limit, pr_bumps_version, reply_hook, govern_hook, agent_files, routines. Each prints as its own `held: <key> = <value> (unattended or runs code; add --allow <key> to take it)` line in the dry run and the run, and is taken only when named with `--allow KEY[,KEY]`. Every value, held or borrowed, passes the private-value check before it is printed: a failing value prints as `held: <key> (holds a private value; not shown)` (or `skip:` for a borrowed one) and is left out even with `--allow`. An `--allow`ed value is screened by the same check, and again by the SET-8 guard at staging, before it lands in the written config. This repo's own keep: base, agent_command (permissions are the owner's), version_file, template_*, session_command, digest_owner.
- Milestone layout: milestones are free form, so none is created or copied; the layout that remains is how issues are grouped, so `feature_labels` and the model's page set shape are borrowed. A page in the model with no matching area in this repo is listed `skip:`; an old model that still holds milestones gets `skip: milestone <title> (free form, none made)`.
- Private rules, never values: the model's `risky_paths` regexes are borrowed; the model's local rules and leak patterns live in the owner's private folder (machine-wide), so only a line `NOTE: your local layer already applies here` is printed and no private file is read. Every borrowed value passes a private-value check (a home path, an email, a token-looking string, a match in the owner's private-name list): a failing value is `skip: <key> holds a private value` and never printed.
The borrowed values land through the normal config merge (this repo's own existing values still win), so a second run changes nothing.

**SET-7 dry run lists everything; second run changes nothing.** `seed.decide` also plans the rendered `docs/wiki/Tests.md`, the `.gitignore` conversion, the git hooks, `borrow:` lines, `WOULD FILE`, and (always) prints the private half's keys as `would add to <private folder>`. The test is an invariant, not a sample: the set of files in the real run's adoption commit is a subset of the dry run's `add:`/`convert:` paths, and a dry run leaves the tree, branches and the home folder byte-identical. A working-tree config (untracked or ignored) is read before the HEAD or branch copy (never overwritten). Second run: no commit, no gh write, `NO CHANGE`, and the two health lines above are still printed.

**SET-8 refuse local settings and private values.** `adopt.guard_staged()` runs after staging and before the commit, next to the existing `private.py hook staged` call, and looks only at lines the adoption adds (the staged diff against HEAD), never at text the repo already had, so adopting a repo whose README already holds its author's email or a long local-looking string is not refused. It refuses (rollback, exit 1, naming `file:line` or the key, never the value) when an added line holds (a) a private-home key in `.loop/config.json` (for example `allowed_tools`, `leak_prefixes`, `full_markers`, `overrides`, `probe`), (b) the owner's home folder path or the git user email as an exact substring, or (c) an exact value of a local-layer string setting that looks like a path or an address (holds `/`, `~` or `@`, 8 or more characters) and is not a template default (defaults come from the `settings.py` table). There is no length-only rule. The values are read only to compare and are never echoed. These three refusals are the only ones about content, and they apply to what setup is about to write (including borrowed `--from` values), not to pre-existing user text.

**Size.** Measured: `setup.py` is 17243 bytes (health warns at 18432); `reply_hook()` with its `HOOKS` table is 4892 bytes. Step zero is a pure move of both into `hooks.py` (setup keeps the dispatch and the shared `refuse()`), the same pattern as the size-139 to size-141 moves, leaving `setup.py` at about 12350 bytes. The wiring this goal adds to `setup.py` (the `Txn` calls, gap collection, the two health calls, `--from`, `--no-issues`, `--no-health`) is budgeted at 2500 bytes, so it ends near 14900 and leaves about 3500 bytes for ci-minutes-template before the warning line; anything past the budget moves into `adopt.py`. The size row (`scripts` rule) is the proof.
