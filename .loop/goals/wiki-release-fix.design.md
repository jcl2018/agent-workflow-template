## Problem

On main at v0.27.17 (settings-table release), `bash dev/toy/ci-env.sh bash dev/toy/test-wiki.sh` fails: the toy goal stops with "goal did not reach a pull request", so the wiki-release regression row is red.

## Cause

v0.27.17 made `render.render()` in `skills/workflow-docs/scripts/render.py` (what `criteria.py render` runs) call `refresh()` unconditionally. `refresh()` rewrites the Settings and Automation blocks in Home.md and README.md and the README template line. Everywhere else those blocks are a criteria-on feature: `docs.py check` (`problems()` -> `render.stale_blocks()` -> `refresh(root, True)`, under `if config(root).get("criteria")` at docs.py:186), `docs.py publish` (line ~298, `render.refresh(root)` under `if config(root).get("criteria")`) and the workflow-docs SKILL.md all gate them on `"criteria": true` in `.loop/config.json`.

The chain in the toy:
1. test-wiki.sh runs a criteria-off toy repo and changes its config (`auto_merge: true`), so the rendered Settings block no longer matches README.md.
2. The QA lane's prep (`skills/workflow-delivery/scripts/lanekit.py prep`) runs `criteria.py render` before any row.
3. render() now rewrote README.md's Settings block. README is not a prep path (prep only commits wiki pages whose edits sit inside `## Tests`, or Tests.md, plus regression-runs.tsv), so README stays dirty.
4. The lane refuses with LANE_DIRTY ("a row left README.md"), the flow stops at qa, and `goal.py pr` refuses: no pull request.

## Which side was wrong

The code was wrong, not the test. test-wiki.sh exercises a legitimate criteria-off repo whose config changes mid-goal; nothing it does is unusual. The faulty change is v0.27.17's unconditional `refresh()` call in `render.render()`, which broke the existing criteria gate that docs.py check/publish and SKILL.md promise.

## Chosen fix (Approach A, committed as 7e47366)

One line in `render.render()`: run `refresh(root, args.check)` only when `config_of(root).get("criteria")` is truthy, matching docs.py check/publish. Criteria-off repos get the pre-v0.27.17 behaviour back (render touches only the Tests tables); criteria-on repos are unchanged. No new file under skills/; setup.py is not touched.

## Alternatives considered

- **B: widen lanekit's allowed prep paths to README.md and Home.md's Settings/Automation blocks.** Rejected: it treats the symptom in one caller. The lane would commit README rewrites in a criteria-off repo that never opted into those blocks, contradicting docs.py and SKILL.md, and adds block-aware diffing to lanekit (more code in a hot path) while other callers of `criteria.py render` would still write the blocks.
- **C: put the criteria gate inside `refresh()` itself.** Rejected for now: `docs.py publish` and `render.front()` already gate before calling it, so the gate would be duplicated, and `refresh()` stays a plain writer that callers decide to run. A is the same guard at the one ungated caller.
- **D: change test-wiki.sh (e.g. stop setting auto_merge, or refresh README first).** Rejected: the test was right; editing it would hide a real regression that any criteria-off user hits on a config change.

## Risks

- **Criteria-on repo whose config changes mid-goal.** With criteria on, prep's render still rewrites README.md/Home.md blocks, which are not prep paths, so a later lane could hit LANE_DIRTY the same way. This is not new in v0.27.17's design intent (criteria-on repos are expected to keep the blocks fresh, and `docs.py check` flags them stale), and it is outside this goal's done lines. Mitigation noted as a follow-up: the command that changes config, or the prep commit, should carry the refreshed blocks in criteria-on repos. Not done here to keep the fix one line and setup.py untouched.
- **A caller that relied on render() refreshing blocks in criteria-off repos.** None found: the only other `refresh()` callers are docs.py publish (gated at docs.py:298) and `render.stale_blocks()` (check-only, `refresh(root, True)`, reached from docs.py `problems()` under the criteria gate at docs.py:186). `render.front()` does not call `refresh()`; it is the gated DOC-4/DOC-5 format check through `contract()`.
- **`config_of` read per render.** Negligible cost; it is already used in render.py.
