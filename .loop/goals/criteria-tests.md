## Done lines

Frozen. A wrong done line needs a new goal.

1. Each feature page has a Criteria section of at most 6 short, high-level, PRD-style statements in plain words with no script names, each marked Unreviewed or Reviewed with a date
2. docs.py check fails when a goal changes the wording of a Reviewed criterion; changing one requires the owner to mark it Unreviewed first, and the SKILL file says so
3. Under the criteria, a Tests table lists for each criterion the tests that enforce it, each linked to a regression row with its last run status and date, and a criterion with no passing test shows as not enforced
4. Every criterion has at least one regression row, and the regression workflow on GitHub runs them all and shows status and run history
5. Feature pages drop everything else, such as charts and command detail, or move it to README and the SKILL files, so a page is only Summary, Criteria and Tests
6. Documentation is converted first as the template, then Delivery, Monitoring, Regression, Release and Health, and docs.py check passes on all of them with existing criteria kept as Unreviewed unless already reviewed
7. A toy test proves the format check, the reviewed-criterion lock and the not-enforced marker, and every script stays under 20 KB

## Design

Reviewed by /autoplan (unattended, recommended answers taken). Builds on the criteria-contract work already in the repo: `criteria.py` (review, sync, seals), `docs.py` (section rules, `SCRIPT`/`CHART` checks), `regression.py criteria`, `release.py` criteria refusal. This goal changes the page shape and the lock, not the opt-in switch (`"criteria": true`).

- Page shape becomes `Summary`, `Criteria`, `Tests` (done line 5). `Commands` and `Enforced by` go; `Commands` content moves to the owning SKILL.md, flow charts to README or the SKILL file. The `CHART`, `SCRIPT` and `Commands` checks go with them.
- A criterion line is `- DOC-4: **Unreviewed** text` or `**Reviewed 2026-11-07**`, at most 6, no script names (the `SCRIPT` check narrows to Criteria text only).
- `Tests` is a table, one row group per criterion: regression row id (linked to its row), last status, last date. A criterion with no passing row shows `not enforced`. The status and date come from a committed ledger `.loop/regression-runs.tsv` (row id, status, date) that `regression.py` writes on every row run; the table is regenerated by a docs.py/regression.py render step, never hand-edited, and `check` fails a stale table.
- Reviewed lock: `check` compares each Reviewed line with its seal (existing `seal`) and fails on a mismatch; only `criteria.py review` and an owner-set back to Unreviewed clear it. This reverses DOC-9 ("no check blocks a change"); `sync` stops auto-returning lines and the SKILL file says the owner marks a criterion Unreviewed first.
- CI: the existing `.github/workflows/regression.yml` already runs every `land`/`nightly` row and keeps run history in Actions. Add a job summary table (row, PASS/FAIL) so status is visible per run. Criterion rows must be `land` or `nightly` so CI runs them (done line 4); `regression.py sync` reports any criterion whose rows are not.
- Size: `docs.py` is 20425 B and `release.py` 20410 B against a 20480 B cap. Move the new page parsing and table render into `criteria.py` (6.6 KB) or a new `criteria_tests.py`, and shrink docs.py by the dropped Commands/chart code. Scripts stay standalone (no cross-skill imports): `regression.py` and `release.py` keep their own small readers, so the new Criteria/Tests format must be parsed in 3 places; keep each reader under ~15 lines.

## Plan

1. Format and lock in the docs scripts: new section list, criterion regex with Reviewed date, lock check, drop CHART/SCRIPT-on-Commands code; proves done lines 1, 2 (toy: format check, reviewed-criterion lock).
2. Ledger and Tests table: `regression.py` writes `.loop/regression-runs.tsv`; render step builds the table, `check` fails stale/`not enforced` mismatches; proves line 3.
3. Regression readers: `regression.py sync/criteria`, `release.py`, `health.py` read `## Criteria` + id→row links from the new format; CI job summary; proves line 4.
4. Convert Documentation first (template), then Delivery, Monitoring, Regression, Release, Health; move dropped detail to README/SKILL files; add a regression row per criterion; existing criteria keep their ids and stay Unreviewed; proves lines 5 and 6.
5. SKILL.md for workflow-docs states the lock rule and the new shape; update `skills/loop-files.md`, `listing.json`, `.loop/docs.tsv`; toy test `dev/toy/test-criteria.sh` extended for format, lock and `not enforced`; size assertion for every script (line 7).

## Risks

- Retiring the old rows (`four-sections`, `flow-charts`, `names-enforcer`, `change-not-blocked`, `returned-on-change`) and adding new ones: a row seen failing is required before it counts as proven, so each new row needs a `seen_red` run.
- Three parsers of the same format can drift; one toy fixture per parser.
- Home and Milestones are not feature pages in the goal's list; they stay exempt.
