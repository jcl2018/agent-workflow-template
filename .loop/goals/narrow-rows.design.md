## Problem Statement

v0.11.0 (test-lanes) made `regression.py run --reuse` rerun only the rows a change can affect, using `lanes.py` to map
changed files to rows. On this repo it never narrows anything. Measured on main at v0.13.1: a one-file change to any
file under `skills/` reruns all 172 land rows. Two causes, both in `lanes.py`:

1. `widen()` turns every skill path a script names into its whole skill folder (`skills/workflow-x/`), and
   `SKILL_NAME` adds a skill folder for every bare `workflow-x` word in a file.
2. `closure()` then walks those folders and scans every file in them, so the dependency set of every toy script grows
   to cover every skill.

Many toy scripts also name folders on purpose (`m="python3 $here/skills/workflow-monitoring/scripts"`, then `$m/watch.py`),
so even exact path matching would see a folder, not the files.

The goal: each toy test script declares the files it exercises, and `lanes.py` maps a changed file to rows from those
declarations, so a one-file change in one skill reruns only the rows that test it.

## What Makes This Cool

qa runs the full land suite once; ship and pr reuse it. Today any code change in ship or after a base merge reruns all
172 rows (about the full suite's time). Narrowed, a fix to `health.py` after qa reruns only the health rows. The table
of "which rows does this file feed" also becomes something a person can read in each toy script's header.

## Constraints

- Every script stays under 20 KB. `lanes.py` is 10.6 KB, so there is room; `regression.py` is 19.9 KB and gets no
  new code.
- The operation session asked this worker to keep edits to `lanes.py`'s row mapping and the per-script declarations.
  regression-summary works in `skills/workflow-regression` and `dev/toy` at the same time (summary and rendering), so a
  merge is expected at the end.
- Safety comes first. A wrong narrowing skips a row that should have run; the CI plain run still runs everything, but
  the lane is what gates ship and pr. When in doubt, rerun.
- Consumer repos that adopt the template have their own row tables with no declarations. Their behaviour must not get
  less safe.
- Done lines are frozen (see `narrow-rows.md`).

## Premises

1. The declaration belongs in the toy script, next to the code that runs the skill scripts, not in `regression.tsv`
   (172 rows share 37 scripts; one header per script is 37 edits, not 172, and stays next to what it describes).
2. A declaration names entry files. `lanes.py` follows what those files reach on its own (Python imports, quoted
   script and data file names, sourced shell files), without widening to folders. Authors are not asked to list
   transitive files by hand.
3. A script with no declaration keeps today's wide mapping. A row whose dependencies cannot be worked out reruns on
   every change. Neither path ever skips a row.
4. A changed file that no row reads still forces a full run (today's UNMAPPED rule stays).

All four auto-agreed (unattended run: recommended answers).

## Approaches Considered

### Approach A: per-script `# reads:` header, narrow closure (chosen)

Each `dev/toy/test-*.sh` gets one or more comment lines `# reads: <path> <path> ...` naming the skill scripts and data
files it runs. `lanes.py` reads the header of every file a row command names. If one has a declaration, the row runs
in narrow mode: its dependencies are the script, the declared paths, the exact files the script names literally, and
the narrow closure of those. Otherwise the row keeps today's wide closure.
Effort S-M. Risk low-medium (a missed transitive edge skips a row; mitigated by the closure rules and the toy test).
Reuses `references()`, `scan()`, `hits()`, `plan()`.

### Approach B: trace file reads at run time

Record which files each row opens during qa's full run (an audit hook through `sitecustomize`, or `fs_usage`/`strace`)
and store them per row in the record. Exact, but bash reads are invisible to a Python hook, `fs_usage` needs root on
macOS, and the record would hold machine paths. Rejected: platform-bound and heavier than the goal needs.

### Approach C: map by requirement

Map rows to skills by their PRD requirement prefix (`REG-*` to workflow-regression, `MON-*` to monitoring). Cheap, but
wrong for the many cross-skill rows (a `MON` row drives `goal.py`, `setup.py` and `merge.py`). Rejected: unsafe.

## Recommended Approach

Approach A.

### Declaration format

- A line in the script's first 40 lines, matching `^#\s*reads:\s*(.+)$`. Several lines add up.
- Each word is a repo-relative path. A file is a file. A path ending in `/` is a folder prefix (allowed for honest
  cases such as `dev/toy/repo/`, which `make.sh` copies whole; never for a skill's `scripts/` folder).
- The script itself is always a dependency; it need not list itself.

### Narrow closure (declared rows)

Starting set: the script, its declared paths, and the exact existing files the script names literally (no folder
widening). Folder mentions are handled fail-safe, in the declared script and in every `.sh` file it reaches:

- A folder outside `skills/` (for example `dev/toy/fakegh/`, `dev/toy/repo/`) stays a prefix dependency, as today.
  Nothing outside `skills/` is ever dropped.
- A skill folder (`skills/<s>/` or `skills/<s>/scripts/`, including the `$M/watch.py` variable form) is replaced by
  the declaration only when the declaration names at least one file inside it. If it names none, the row goes to the
  always set with reason `names skills/<s>/scripts/ but declares no file in it`.
- Under-declaring through a folder variable is caught automatically, across files: once any file in the row's narrow
  closure mentions a skill folder, every file of that folder whose base name appears in any file of the closure (the
  declared script plus every reached `.sh`) is a dependency, declared or not. A script
  that sets `m=.../workflow-monitoring/scripts`, runs `$m/watch.py` and `$m/board.py` and declares only `watch.py`
  still depends on `board.py`. Only a name built at run time (`$f.py` in a loop) escapes this, and the build step
  declares those by hand (see Open Questions).
- A bare `$here/skills` (the whole tree, as in `cp -R "$here/skills"` or `find "$here/skills"`) needs the declaration
  `skills/`; without it the row goes to the always set. A script that honestly reads every skill stays wide for all
  its rows.

### Rows that name several files, and helpers

A row command can name several files (`bash dev/toy/ci-env.sh bash dev/toy/test-docs.sh`). Each named file is
resolved on its own and the row's dependencies are the union:

- A named file with a declaration, or reached from one: the narrow closure below.
- A named file with no declaration and not reached from a declared one: today's wide closure. So a row runs narrow
  only to the extent that every file it names is narrowed; an undeclared file can only add dependencies.
- Helpers reached from a declared script (`make.sh`, `fakegh/gh`, `flow-done.sh`, `ci-env.sh` when sourced or run)
  are followed with the narrow rules, including the fail-safe folder rules above. They need no header; a `# reads:`
  line in any reached file is honoured and adds its paths.

Then follow, for each file reached:

- `.py`: same-folder `import` / `from` modules (today's rule), and every quoted literal that looks like a file name
  (`"docs.py"`, `"template.md"`, `"settings.md"`). A literal resolves to files with that base name in the same skill
  folder; if none, to files with that base name anywhere under `skills/`. Base names are unique in `skills/` except
  `SKILL.md` and `commands.md`, which resolve to the same skill first. This catches `os.path.join(HERE, "..", "..",
  "workflow-docs", "scripts", "docs.py")` and helper calls like `script("watch.py", ...)` without reading folders.
- `.sh`: sourced files (`. file`, `source file`) and exact existing files it names (no widening).
- Other files (`.md`, `.json`, data): leaves. Their contents are not followed (a SKILL.md names every script; following
  it would undo the narrowing).

### Cannot be worked out: always rerun

A row reruns on every change (it joins the `always` set today used for commands that name no path) when:

- its command names no repo path, or names the repo root (today's rule);
- a declared path does not exist, or contains `$`, `*` or `?` (a declaration that cannot be resolved is never trusted
  to narrow).

The `FULL`/`AFFECTED` output prints one note per such row: `ALWAYS <id>: <reason>`.

### What stays as it is

- Undeclared scripts and rows: today's wide closure. Consumer repos see no change.
- The `.loop/regression.tsv` rule (an edited row reruns; any edit reruns rows that reach `regression.py`), the known
  list rule, release files (`NO_EFFECT`) and UNMAPPED full runs.
- The record format and runner hash (a `lanes.py` change invalidates old records, so the first run after this lands is
  full).

### Measuring on this repo

`lanes.py` gains a small read-only entry, `python3 lanes.py affected [--level land] PATH...`, printing
`AFFECTED n of m rows` and the row ids a change to those paths would rerun on this repo's table (the same `plan()`
decision as a reuse run, with every row's prior result assumed). The PR body shows a table: for one file per skill,
rows rerun before (172 of 172) and after.

### Toy test

A new section of `dev/toy/test-lanes.sh` builds a toy repo with two fake skills, two declared scripts and one
undeclared script, and proves:

- a change to one skill's script reruns only the rows whose declared closure reaches it (narrow);
- a change to a file every declaration reaches (a shared helper) reruns all rows (wide);
- a change reached only through a quoted file name in a Python script reruns its row;
- a row whose declaration names a missing path reruns on an unrelated change;
- a declared script that uses an undeclared helper folder outside `skills/` still reruns when a file in that folder
  changes, and one that names a skill scripts folder without declaring a file in it reruns on any change;
- an undeclared script still reruns on a change in any file its wide closure covers.

Each becomes a `regression.tsv` row under REG-6 and a Given/When/Then scenario on `docs/wiki/Regression.md`, seen
failing once (`regression.py red <id> --break`) and passing.

## Open Questions

- Do any toy scripts reach a skill file only through a computed name (a loop variable such as
  `for f in watch board board_page; do ... $f.py`)? Those must be declared by hand; the build step checks every
  `$here/skills` use per script.
- Docs pages under `docs/wiki/` and SKILL.md files: if no row reads them, a goal that edits code and docs together
  still gets a full run (UNMAPPED). The measurement will say how often that happens; narrowing that is out of scope.

## Success Criteria

- Every `dev/toy/test-*.sh` named by a row has a `# reads:` header with no skill `scripts/` folder in it.
- Done line 2, made checkable. A row "belongs to" skill S when the declaration of a script it names lists a file of
  S directly. A file of S is a "leaf" when no script of another skill reaches it. For a leaf script file of each skill,
  `lanes.py affected <file>` reruns only rows that belong to S, and fewer than all land rows. A file other skills reach
  (for example `regression.py`, which health.py runs) reruns the rows of S plus the cross-skill rows whose closure
  reaches it, and the PR table marks those as cross-skill. The PR shows, for every script file in `skills/`, rows rerun
  before and after, and the belongs-to check for each leaf.
- The toy test passes; the full land suite passes once in qa.
- Done line 5: each done line has a Given/When/Then scenario under REG-6 linked to its row with its last result.

### R3-1 — feasibility (blocking)

**Problem**

> The new base-name rule scans only 'the script' for base names. The folder rules apply in the declared script and in every .sh file it reaches, so the folder mention and the `$m/<name>` uses can sit in different files. Example: a sourced helper (ci-env.sh, make.sh) sets `m=.../workflow-monitoring/scripts`, and the declared test script runs `$m/watch.py` and `$m/board.py` but declares only watch.py. The helper's text holds the folder mention but not `board.py`. The test script's text holds `board.py` but no folder mention. Read literally, neither file triggers the rule, so the board.py edge is lost and a change to board.py skips the row. That breaks 'never skipped'. It is also unclear whether 'the script' means only the declared toy script or each reached file too.

**Remedy**

> State that once any file in the row's narrow closure mentions a skill folder, every file of that folder whose base name appears in any file of the closure (the declared script plus every reached .sh) is a dependency. Or say that a folder variable set in one file and used in another sends the row to the always set.
