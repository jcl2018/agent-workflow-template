# Start here

Generated by `entry.py write` from this repo's PRD pages and `.loop/config.json`. Don't edit it by hand: change a page or a setting, then run `docs.py audit`.

## First five minutes

1. Read this page: how the parts fit together, every feature and how to use it, and every setting.
2. Ask for `workflow-monitoring report` to see what is running and what waits on you.
3. Start a goal by asking for `workflow-monitoring go "goal" --done "line"`.
4. Each skill's Command map, in its SKILL.md, names the exact script behind every ask.

## Loop

A goal is one sentence with frozen done lines. A worker takes it through idea, plan, build, review, qa, ship, pull request and release, on branch `loop/<slug>` cut from `main`. Each step's skill is chosen in the private flow file, `~/.workflow-loop/flow.json` (`built-in` runs delivery's own routine). Review is the only gate. Plan and review run at `full` depth; auto-approval is `true`; a goal stops after 3 failed tries; its token budget is 3000000 (0 means none).

## Release

Release is a goal's last step: it brings the docs up to date, bumps `VERSION` and writes the release note. Auto-merge is `true`; a pull request bumps the version itself: `false`. Your own routines after a release: none.

## Operation and workers

One session governs and the others build: the operation session assigns goals, watches them and answers what waits on you, and never builds. Up to 0 workers run at once (0 means no limit). It checks in every 30 minutes; mending a failed goal is `true`, resuming after a usage limit is `false`, and watch looks again every 20 seconds.

## Docs

Feature pages live in `docs/wiki`, one PRD page per feature with numbered requirements, at most 6 each. The criteria contract is `true`. The docs command finds stale pages, and the release step rewrites them.

## Regression

Every requirement and every fixed defect has a regression row in `.loop/regression.tsv`, seen failing before its fix. The land lane runs once per goal, in qa, within 600 seconds; the scheduled run is `17 */4 * * *`.

## Health

Health checks the repo with fixed rules that give the same answer every time, on the schedule `47 */4 * * *`; a branch or worktree older than 14 days is stale. The judge's environment: ANTHROPIC_API_KEY.

## Settings

Every repo setting, its value and its one-line explanation is in the Settings table below; add any missing one with `/workflow-setup fill-repo`. Private settings live in `~/.workflow-loop/` and never appear here.

## Settings table

| Setting | Value | What it does |
|---|---|---|
| `agent_command` | ["claude", "-p", "--model=sonnet", "--allowedTools=Bash,Read,Write,Edit,Skill"] | The command that runs a goal in the background; the prompt is its last argument. |
| `agent_files` | ["CLAUDE.md", "AGENTS.md"] | Agent entry files setup wires the workflow-loop block into; [] turns wiring off. |
| `auto_approve` | true | true approves what a flow step leaves for the owner, logged as auto-approved. |
| `auto_merge` | true | true lets the release step merge a goal's pull request and publish its release. |
| `base` | main | The branch goals start from and pull requests target. |
| `cadence` | 30 | Minutes between check-ins of the operation session, 1 to 60, or off. |
| `criteria` | true | true makes docs check enforce the PRD page contract (Problem, Requirements, Non-goals, Success metrics, Tests). |
| `criteria_max` | 6 | Most criteria a wiki page may hold, 1 to 50; docs check and health fail a page over it. |
| `digest_owner` | none | Who the digest comment mentions; empty means the repo owner (an organisation notifies no one). |
| `health_cron` | 47 */4 * * * | Five cron fields: when the health routine and its digest run in GitHub Actions; off turns it off. |
| `judge_command` | ["claude", "-p", "--tools", ""] |  |
| `judge_env` | ANTHROPIC_API_KEY | The Actions secret holding the agent key; the scheduled judge runs only when it is set. |
| `judge_setup` | none | A command the scheduled health run uses to install judge_command's program, run only with the secret. |
| `limit_wait` | 1800 | Seconds to wait after a usage limit before resuming. |
| `max_tries` | 3 | Failed tries a goal gets before it stops and files a finding. |
| `mend` | true | true lets watch start a fresh agent for a failed goal. |
| `mend_wait` | 120 | Seconds a failed goal waits before a mender starts. |
| `parallel` | 0 | Workers running at once; 0 means unlimited. |
| `pr_bumps_version` | false | true moves the last number of the version file once on a goal's branch. |
| `regression_cron` | 17 */4 * * * | Five cron fields: when the regression routine runs in GitHub Actions; off turns it off. |
| `reply_hook` | true | false turns off the reply-format hook (setup.py --reply-hook installs it) in the operation session. |
| `resume_on_limit` | false | true lets watch resume a goal that hit a usage limit. |
| `review_depth` | full | full runs the plan and review skills' whole pipeline and refuses a condensed one; condensed allows a shorter run. |
| `risky_paths` | ["^\\.github/", "(^\|/)auth", "(^\|/)migrations?/", "(^\|/)(schema\|data)\\b"] | Regexes for paths whose goals need extra care. |
| `routines` | none | Commands the release step runs on the base branch before it merges. |
| `stale_branch_days` | 14 | Days a local branch on no remote may sit before health lists it with its removal command. |
| `step_limit` | 0 | Seconds one flow step may run when the flow file sets no limit; 0 means the built-in limit. |
| `template_repo` | (empty) | The template's GitHub repo (owner/name) update reads releases from, when the installed package names none. |
| `test_budget_seconds` | 600 | Seconds the land test lane may take before health warns and names its slowest rows. |
| `time_budget_minutes` | 120 |  |
| `token_budget` | 3000000 | Tokens a goal may spend over all steps before no new step starts; 0 means no budget. |
| `version_file` | VERSION | The file that holds the version; a release bumps it and writes the changelog. |
| `watch_interval` | 20 | Seconds between rounds of watch. |
| `wiki_dir` | docs/wiki | The folder of wiki pages. |
