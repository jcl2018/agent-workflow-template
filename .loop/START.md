# Start here

Generated by `entry.py write` from this repo's PRD pages and `.loop/config.json`. Don't edit it by hand: change a page or a setting, then run `docs.py audit`.

## First five minutes

1. Read this page: how the parts fit together, every feature and how to use it, and every setting.
2. Ask for `workflow-monitoring report` to see what is running and what waits on you.
3. Start a goal by asking for `workflow-monitoring go "goal" --done "line"`.
4. Each skill's Command map, in its SKILL.md, names the exact script behind every ask.

## Loop

A goal is one sentence with frozen done lines. A worker takes it through idea, plan, build, review, qa, ship, pull request and release, on branch `loop/<slug>` cut from `main`. Each step's skill is chosen in the private flow file, `~/.workflow-loop/flow.json` (`built-in` runs delivery's own routine). Review is the only gate. Plan and review run at `full` depth; auto-approval is `true`; a goal stops after 3 failed tries; its token budget is 3000000 (0 means none).

## Release

Release is a goal's last step: it brings the docs up to date, bumps `VERSION` and writes the release note. Auto-merge is `true`; a pull request bumps the version itself: `false`. Your own routines after a release: none.

## Operation and workers

One session governs and the others build: the operation session assigns goals, watches them and answers what waits on you, and never builds. Up to 0 workers run at once (0 means no limit). It checks in every 30 minutes; mending a failed goal is `true`, resuming after a usage limit is `false`, and watch looks again every 20 seconds.

## Docs

Feature pages live in `docs/wiki`, one PRD page per feature with numbered requirements, at most 15 each. The criteria contract is `true`. The docs command finds stale pages, and the release step rewrites them.

## Regression

Every requirement and every fixed defect has a regression row in `.loop/regression.tsv`, seen failing before its fix. The land lane runs once per goal, in qa, within 600 seconds; the scheduled run is `17 */4 * * *`.

## Health

Health checks the repo with fixed rules that give the same answer every time, on the schedule `47 */4 * * *`; a branch or worktree older than 14 days is stale. The judge's environment: ANTHROPIC_API_KEY.

## Settings

Every repo setting, its value and its one-line explanation is in the Settings table below; add any missing one with `/workflow-setup fill-repo`. Private settings live in `~/.workflow-loop/` and never appear here.

## Settings table

|---|---|---|

| `agent_files` | ["CLAUDE.md", "AGENTS.md"] | Agent entry files setup wires the workflow-loop block into; [] turns wiring off. |
| `auto_approve` | true | true approves what a flow step leaves for the owner, logged as auto-approved. |
| `auto_merge` | true | true lets the release step merge a goal's pull request and publish its release. |
| `base` | main | The branch goals start from and pull requests target. |
| `cadence` | 30 | Minutes between check-ins of the operation session, 1 to 60, or off. |
| `criteria` | true | true makes docs check enforce the PRD page contract (Problem, Requirements, Non-goals, Success metrics, Tests). |
| `criteria_max` | 15 | Most criteria a wiki page may hold, 1 to 50, default 10; docs check and health fail a page over it. |
